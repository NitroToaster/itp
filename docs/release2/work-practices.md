# Work Practices

This document describes how the members of group 36 cooperate and structure the workload. 

## Team setup

- Group 36 consists of 6 members.
- Meeting time: Tuesdays, 08:15-10:00.
    - Additional meetings are scheduled on demand, does not have to include the whole group. 
- Coding style: Alone or in pairs. 

## Meetings

### Main meeting

- Each tuesday 08:15-10:00
- Each group member presents individually or in pairs:
    - Progress; what has been done since last meeting. 
    - Plans; what is the plan for the coming week? Coordinating issues according to each member's workload.
    - Problems; which, if any, problems have been encountered? What could possibly become future problems?
- Discuss the outlook for the coming week. Create and delegate new issues if necessary. 
- See [release2/meetings](./meetings/) for proceedings.

### Additional meetings

- Usually internal backend or frontend meetings. 
- Provides a platform to properly coordinate new implementations.
- Meetings with the teaching assistant does not include the PPP structured. They are structured as a feedback session followed by Q&A.

## Communication

In addition to weekly and additional meetings, the group has a Slack workspace for project-related communication. The workspace is divided into five channels: 

- Backend; all discourse surrounding backend
- Frontend; all discourse surrounding frontend
- Meetings; room booking, request extra meetings, share proceedings
- Pull-requests; coordinating and notifying PRs
- Things-to-do; additional information and delegation about upcoming tasks

## Collaboration practices

As a change from release 1, the group has set a goal to work in pairs more often. This allows fluent communication, ensures code quality and coherent logic between modules.
